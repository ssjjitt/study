
## Ответы на вопросы

### 1. Что такое unit-тест. Назначение.

**Unit-тест** (модульный тест) - это тест, который проверяет работу отдельной единицы кода (функции, метода, класса) в изоляции от других частей приложения.

**Назначение:**
- Проверка корректности работы отдельных компонентов
- Раннее обнаружение ошибок на этапе разработки
- Документирование ожидаемого поведения кода
- Упрощение рефакторинга (уверенность, что изменения не сломали функциональность)
- Повышение качества кода и архитектуры

В нашем проекте unit-тесты проверяют работу BLoC'ов и сервисов с использованием Mockito для изоляции зависимостей.

### 2. Что такое widget-тест. Назначение.

**Widget-тест** (виджет-тест) - это тест, который проверяет работу отдельных виджетов Flutter в изоляции, но с учетом их взаимодействия с Flutter framework.

**Назначение:**
- Проверка правильности отображения UI-компонентов
- Тестирование взаимодействия пользователя с интерфейсом (нажатия, ввод текста, жесты)
- Проверка реакций виджетов на изменения состояния
- Быстрое обнаружение проблем с UI без запуска всего приложения
- Проверка навигации между экранами

В нашем проекте widget-тесты проверяют:
- Ввод текста в поля формы (enterText)
- Нажатия на кнопки (Tap)
- Перетаскивание элементов (Drag)

### 3. Что такое integration-тест. Назначение.

**Integration-тест** (интеграционный тест) - это тест, который проверяет работу нескольких компонентов приложения вместе, включая взаимодействие с внешними системами (база данных, API, файловая система).

**Назначение:**
- Проверка взаимодействия между различными модулями приложения
- Тестирование полных пользовательских сценариев
- Проверка интеграции с внешними сервисами (Firebase, API)
- Обнаружение проблем, которые не видны в unit/widget тестах
- Валидация end-to-end сценариев использования приложения

В нашем проекте integration-тесты проверяют:
- Добавление отеля администратором
- Работу с избранным пользователя
- Просмотр информации о текущем пользователе

### 4. Библиотека Mockito. Назначение.

**Mockito** - это библиотека для создания мок-объектов (заглушек) в тестах.

**Назначение:**
- Создание фиктивных объектов для замены реальных зависимостей
- Изоляция тестируемого кода от внешних зависимостей
- Контроль поведения зависимостей в тестах
- Проверка взаимодействия между объектами (вызовы методов, передача параметров)
- Упрощение тестирования сложных систем с множеством зависимостей

**Преимущества использования Mockito:**
- Быстрые тесты (не требуют реальных подключений к БД, API и т.д.)
- Предсказуемость (можно настроить точное поведение моков)
- Изоляция (тесты не зависят от внешних факторов)
- Гибкость (легко менять поведение моков для разных сценариев)

В нашем проекте Mockito используется для создания моков:
- FirestoreService - для тестирования BLoC'ов без реального подключения к Firebase
- AuthService - для тестирования аутентификации без реального Firebase Auth
- Других сервисов для изоляции тестируемых компонентов

## Примеры использования Mockito

```dart
// Создание мока
@GenerateMocks([FirestoreService])
class MockFirestoreService extends Mock implements FirestoreService {}

// Настройка поведения мока
when(mockFirestoreService.getHotels()).thenAnswer(
  (_) async => [testHotel],
);

// Проверка вызовов
verify(mockFirestoreService.getHotels()).called(1);
```

## Примечания

- Для запуска integration-тестов требуется настроенное окружение Firebase (можно использовать Firebase Emulator Suite)
- Mock-файлы генерируются автоматически с помощью build_runner
- Все тесты написаны с использованием best practices Flutter тестирования
